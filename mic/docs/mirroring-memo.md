# Памятка: заявки по объектам и клиникам в YouTrack

Состояние на 28.10.2026. Что сделано в боте техподдержки MAX и в YouTrack,
как заявка клиники попадает инженеру и как клиника видит только своё.

## Коротко

- Отдельные проекты на каждый объект **не создавались**. SupportMG и
  SupportUnimed были раньше, бот ими не пользуется.
- Все заявки из бота идут в один проект **MIC «Сопровождение МИЦ»**. Он остаётся
  хабом: инженеры работают и пишут комментарии только там.
- Клиника видит в MIC **только свои задачи**: у каждой задачи стоит ограничение
  видимости «группа клиники + команда МИЦ». Групп 14, по одной на объект.
- Номер заявки для клиента = номер YouTrack (MIC-20). Задача Planfix создаётся
  следом и называется `[MIC-20] …`, в описании ссылка на YouTrack.
- Инженеры получают уведомления о заявках своих клиник в MAX, с кнопкой
  «В работу». Ответы клиентов тоже приходят им в MAX.

## Путь заявки

1. Пользователь клиники заполняет заявку в боте MAX: тип (Ошибка или
   Доработка), клиника, модуль, роль, суть, шаги, срочность, контакт, файлы.
2. Бот создаёт задачу в YouTrack, проект MIC, с полями и вложениями.
   Пользователю приходит «Заявка MIC-20 принята» и ссылка.
3. Бот создаёт задачу в Planfix (проект 16521, шаблон техподдержки) с теми же
   полями, именем `[MIC-20] …` и ссылкой на YouTrack. Если Planfix на паузе
   по суточному лимиту, заявка ждёт в очереди, номер YouTrack у клиента уже есть.
4. Закреплённому инженеру клиники приходит уведомление в MAX.
5. Комментарий инженера в YouTrack или Planfix уходит клиенту в MAX. Ответ
   клиента из MAX ложится комментарием в обе задачи и приходит инженеру.

Planfix и YouTrack между собой не зеркалятся: у каждой системы своя переписка,
клиент в MAX видит обе.

## Как работает видимость по клинике

У каждой задачи из бота стоит «видят только: группа клиники + Сопровождение
МИЦ Team». Из этого следует:

- **Инженеры** состоят в команде проекта и видят все задачи MIC как раньше.
- **Пользователь клиники**, состоящий в своей группе, открывает проект MIC и
  видит только задачи своего объекта: список, поиск, статусы, комментарии
  инженера. Задачи других клиник для него не существуют, по прямой ссылке
  откроется «нет доступа».
- **Роль групп** в MIC: встроенная Reporter. Читать, комментировать,
  прикладывать файлы, создавать задачи. Менять поля и статусы нельзя.
- Если у клиники группы нет, задача создаётся без ограничения видимости и
  это пишется в лог. Сейчас групп 14 из 14.

Группы, их роль в MIC и видимость старых задач заводит `npm run youtrack:setup`,
повторный запуск безопасен. Скрипт пытался создать отдельную роль «Клиент МИЦ»,
токен не даёт права создавать роли, поэтому Reporter.

## Уведомления инженерам и «В работу»

Инженер подписывается, написав боту в MAX:

    инженер <логин YouTrack> <код>        заявки своих клиник
    инженер все <код>                      заявки всех клиник
    инженер <логин> все <код>              все клиники, «В работу» под своим логином
    инженер стоп                           отписаться

Код хранится на сервере в `/etc/mis-form.env`, переменная `BOT_ENGINEER_CODE`.
Логин должен быть из таблицы инженеров или из `BOT_ENGINEER_LOGINS`
(сейчас там figol_rs и serov_dd).

Уведомление о новой заявке: номер, тип, клиника, приоритет и SLA, суть, модуль,
заявитель, ссылка и кнопки «▶ В работу» и «🔗 Открыть задачу». «В работу»
ставит в YouTrack статус In Progress и Разработчика на нажавшего, уведомление
заменяется отметкой «✅ MIC-20 в работе у …», клиенту в MAX уходит «Заявка
взята в работу. Инженер: …». Для этого логин должен быть в команде MIC.

Ответ клиента по заявке приходит инженеру как «💬 Клиент ответил по MIC-20»
с текстом и ссылкой.

## Что осталось сделать руками

1. **Добавить пользователей клиник в группы** «Клиенты … (объект)». Сейчас
   люди есть только в группе Медгорода, остальные 13 пустые. Без этого клиники
   ничего не увидят. Администрирование → Группы → группа → Пользователи.
2. **Завести аккаунты YouTrack** тем, у кого их нет. Контакты Нефтяника
   стационара из файла: у всех десяти аккаунтов нет.
3. **Планфикс:** добавить «Нигинского» в список поля «Клиника» в шаблоне,
   иначе задача создаётся без этого поля.
4. **Команда MIC:** добавить в команду тех, кто будет брать задачи в работу
   не из пяти инженеров (например serov_dd).
5. По желанию: создать роль «Клиент МИЦ» с нужными правами и перезапустить
   `npm run youtrack:setup`, он переключит группы на неё.

## Где что лежит

- Код бота: `mic/bot/bot.mjs`, YouTrack `mic/bot/youtrack.mjs`, Planfix
  `mic/bot/planfix.mjs`, таблицы клиник `mic/ticket.mjs`, реестр инженеров
  `mic/bot/engineers.mjs`.
- Данные на сервере: `/var/lib/mis-form/` (задачи, подписки инженеров,
  очередь), окружение `/etc/mis-form.env`, логи `journalctl -u mis-bot`.
- Памятка инженерам: `mic/docs/engineer-notify.md`. Поля бота:
  `mic/docs-bot-fields.md`. Первоначальный план и решение: `mic/docs/yt-projects-plan.md`.
- Деплой: `sudo -u deploy git -C /var/www/dotcursor pull --ff-only origin main
  && bash /var/www/dotcursor/mic/deploy/install-mis-form.sh` на сервере.
