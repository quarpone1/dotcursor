# Бот MAX: создание, токен, сертификат Минцифры, подключение к каналу

Короткая инструкция по подготовке бота MAX к отправке сообщений в канал. Результат — два значения, которые нужны любой интеграции (Grafana, Zabbix, скрипты): **токен бота** и **chat_id канала**.

В этом репозитории они кладутся в `/etc/mis-form.env` (или `.env`) как `MAX_ALERT_TOKEN` и `MAX_ALERT_CHAT_ID`, а отправляет сообщения `npm run max:send` — см. [раздел 4.5](#45-отправка-из-репозитория).

> Актуально на сентябрь 2026 года. Интерфейс кабинета MAX и требования платформы меняются; при расхождениях сверяйтесь с `dev.max.ru`.

## 1. Создание бота и получение токена

### 1.1. Требования

С августа 2025 года создавать и публиковать ботов в MAX могут только **верифицированные организации — резиденты РФ** (юрлица; по части источников — также ИП). Физлица и самозанятые не допускаются. Бот создаётся от имени организации, поэтому понадобится доступ к её профилю на платформе для партнёров или помощь того, кто им владеет.

### 1.2. Верификация организации (если ещё не сделана)

1. Откройте платформу MAX для партнёров: `https://business.max.ru` (документация — `https://dev.max.ru/docs/maxbusiness/connection`).
2. Войдите (удобнее с корпоративной почтой) и создайте или выберите профиль организации по ИНН.
3. Пройдите верификацию одним из способов: Госуслуги, Alfa ID, Т‑Business ID, СберБизнес ID. Процедуру проходит руководитель или лицо с правом подписи.
4. Срок — от нескольких минут до 48 часов в рабочие дни. Вопросы — `business_support@max.ru`.

### 1.3. Создание бота

**Через кабинет организации (основной путь):**

1. В профиле организации откройте раздел чат-ботов и создайте нового бота.
2. Заполните карточку:
   - **Имя** — отображаемое название, до 16 символов, например `Grafana Alerts`.
   - **Ник** — уникальный, заканчивается на `bot` или `_bot`, например `clinic_monitoring_bot`.
   - Описание и аватар — по желанию (для модерации лучше заполнить: «Служебный бот мониторинга, публикует уведомления о сбоях в закрытый канал»).
3. Отправьте на модерацию. После одобрения в карточке бота станет доступен **токен**.

**Через @MasterBot в самом мессенджере** (аналог BotFather): найдите `@MasterBot`, нажмите «Начать», отправьте `/create` и пройдите сценарий (ник → имя → токен). В зависимости от текущих правил платформы этот путь может потребовать привязки к верифицированной организации.

### 1.4. Сохраните токен

Токен даёт полный доступ к боту. Не коммитьте его в git и не вставляйте в URL. Храните его в защищённом месте: в файле окружения с правами `600` или в хранилище секретов. Если токен утёк — перевыпустите его в карточке бота.

## 2. Сертификат Минцифры

API MAX переехал с `platform-api.max.ru` на `platform-api2.max.ru` (старый домен отключили 19 июля 2026). Новый домен использует сертификат НУЦ Минцифры. Без корневого сертификата получите `SSL: CERTIFICATE_VERIFY_FAILED`.

Скачайте корневой сертификат «Russian Trusted Root CA» со страницы `https://www.gosuslugi.ru/crt` (на сервере без браузера — скачайте на рабочей машине и скопируйте через `scp`).

Проверьте формат файла:

```bash
head -c 30 russian_trusted_root_ca.cer
# "-----BEGIN CERTIFICATE-----" → PEM, можно использовать как есть
# бинарный мусор → DER, конвертируйте:
openssl x509 -inform DER -in russian_trusted_root_ca.cer -out russian_trusted_root_ca.pem
```

**Вариант А — установить в систему.**

Debian / Ubuntu / Astra:

```bash
sudo cp russian_trusted_root_ca.pem /usr/local/share/ca-certificates/russian_trusted_root_ca.crt
sudo update-ca-certificates
```

RHEL / Oracle Linux / РЕД ОС / ALT:

```bash
sudo cp russian_trusted_root_ca.pem /etc/pki/ca-trust/source/anchors/
sudo update-ca-trust extract
```

**Вариант Б — отдельным файлом** для конкретного приложения, не трогая систему:

```bash
sudo mkdir -p /etc/ssl/max
sudo cp russian_trusted_root_ca.pem /etc/ssl/max/russian_trusted_root_ca.pem
# путь к файлу затем передаётся приложению (например, curl --cacert, CA_BUNDLE, REQUESTS_CA_BUNDLE)
```

Вариант Б надёжнее: обновление пакета `ca-certificates` или пересборка образа его не сломают. Установщик `deploy/install-mis-form.sh` делает именно его: скачивает сертификат, при необходимости переводит DER в PEM и кладёт в `/etc/ssl/max/russian_trusted_root_ca.pem`.

**Node.js (бот и `npm run max:*`).** Node не пользуется системным хранилищем сертификатов, поэтому вариант А ему не поможет. Код бота сам добавляет к доверенным файл `/etc/ssl/max/russian_trusted_root_ca.pem` (другой путь — переменная `MAX_CA_FILE`; PEM и DER подходят оба). `NODE_EXTRA_CA_CERTS` в `.env` не работает: Node читает её только из окружения процесса, а не из `--env-file`.

Проверка:

```bash
curl -sS -o /dev/null -w "%{http_code}\n" https://platform-api2.max.ru/me
# 401 — TLS в порядке (просто без токена). Ошибка SSL — сертификат не подхватился.
# для варианта Б:
curl --cacert /etc/ssl/max/russian_trusted_root_ca.pem -sS -o /dev/null -w "%{http_code}\n" https://platform-api2.max.ru/me
```

## 3. Проверка токена

```bash
export MAX_ALERT_TOKEN='ваш_токен'

curl -sS https://platform-api2.max.ru/me \
  -H "Authorization: $MAX_ALERT_TOKEN"
```

Ожидаемый ответ — JSON с `user_id`, именем бота и `"is_bot": true`.

Обратите внимание: заголовок именно `Authorization: <токен>`, **без** `Bearer`. С префиксом будет `401`.

То же из репозитория (для токена основного бота из `MAX_BOT_TOKEN`): `npm run max:check` — покажет бота, каналы с их `chat_id` и подписки на вебхук.

## 4. Подключение бота к каналу и получение chat_id

### 4.1. Канал

Создайте канал в MAX (например, «Мониторинг — алерты»), если его ещё нет. Сделайте его закрытым: алерты могут содержать имена хостов, IP-адреса и другие внутренние сведения.

> Если создание канала недоступно для вашего аккаунта, подойдёт обычный **групповой чат** — для API разницы нет, меняется только `chat_id`.

### 4.2. Добавление бота администратором

Публиковать в канале могут только администраторы, поэтому:

1. Откройте канал → настройки (название канала вверху) → **Администраторы** (или «Подписчики» → добавить, а затем назначить администратором).
2. Найдите бота по нику (`clinic_monitoring_bot`) и добавьте.
3. Выдайте ему право **публиковать сообщения**. Остальные права (удаление чужих сообщений, управление подписчиками) не нужны.

Для группового чата достаточно просто добавить бота в участники.

### 4.3. Получение chat_id

```bash
curl -sS "https://platform-api2.max.ru/chats?count=100" \
  -H "Authorization: $MAX_ALERT_TOKEN"
```

В ответе будет список `chats`; найдите свой канал по `title`, у него `"type": "channel"`. Нужное значение — поле `chat_id` (обычно это отрицательное число — копируйте вместе с минусом).

Если список пуст — бот ещё не добавлен в канал или не стал администратором. Личные диалоги с ботом в `/chats` не показываются, там только групповые чаты и каналы.

Короче из репозитория: `npm run max:send -- --chats` — печатает `chat_id`, тип и название каждого канала.

### 4.4. Тестовая публикация

```bash
export MAX_ALERT_CHAT_ID='-71234567890'

curl -sS -X POST "https://platform-api2.max.ru/messages?chat_id=$MAX_ALERT_CHAT_ID" \
  -H "Authorization: $MAX_ALERT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "<b>Тест</b>: бот подключён к каналу", "format": "html"}'
```

Сообщение должно появиться в канале от имени канала/бота. Если да — бот готов к использованию: для отправки нужны только токен и `chat_id`.

### 4.5. Отправка из репозитория

Впишите значения в `/etc/mis-form.env` (или `.env` при локальном запуске):

```bash
MAX_ALERT_TOKEN=ваш_токен        # пусто — отправка от MAX_BOT_TOKEN
MAX_ALERT_CHAT_ID=-71234567890
```

и отправляйте:

```bash
npm run max:send -- "<b>Тест</b>: бот подключён к каналу"
echo "Сбой: не отвечает МИС" | npm run max:send       # текст из stdin
npm run max:send -- "текст" --chat -70000000000       # в другой канал
npm run max:send -- "*жирный*" --format markdown      # или plain — без разметки
```

Код выхода `0` — сообщение ушло, `1` — MAX отказал (причина и подсказка в stderr), `2` — не хватает настроек. Текст длиннее 4000 символов обрезается. Проверка на поддельном MAX: `npm run max:test`.

Дальше отправку ведёт сторож `tools/watchdog.mjs`: при заполненном `MAX_ALERT_CHAT_ID` установщик ставит таймер, и сбои формы и бота приходят в канал сами — см. README, раздел «Сторож: тревоги в канал».

Для Zabbix / cron на том же сервере вызывайте напрямую, без npm, от пользователя, которому доступен `/etc/mis-form.env` (права `640 root:deploy` — это root или `deploy`):

```bash
cd /var/www/mis-form && node --env-file=/etc/mis-form.env tools/max-send.mjs "$1"
```

## 5. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `401` на любой запрос | Неверный токен или передан с `Bearer` | Заголовок строго `Authorization: <токен>`; при необходимости перевыпустить токен |
| `404 chat.not.found` | Неверный `chat_id` или бота нет в канале | Повторить `GET /chats`, скопировать `chat_id` вместе с минусом |
| Ошибка прав при отправке | Бот в канале, но не администратор | Выдать право публиковать сообщения |
| `GET /chats` возвращает пустой список | Бот не добавлен в канал | Добавить бота администратором (раздел 4.2) |
| `CERTIFICATE_VERIFY_FAILED` / `curl: (60)` | Нет корневого сертификата Минцифры | Раздел 2 |
| Не резолвится `platform-api.max.ru` | Старый домен отключён | Использовать `platform-api2.max.ru` (в коде — по умолчанию; уберите `MAX_API_BASE`, если он задан) |
| `нет доверия к сертификату` в логе бота | Node не видит сертификат Минцифры | Положить его в `/etc/ssl/max/russian_trusted_root_ca.pem` или указать путь в `MAX_CA_FILE` |

## Итог

После выполнения всех шагов у вас есть:

- `MAX_ALERT_TOKEN` — токен бота;
- `MAX_ALERT_CHAT_ID` — идентификатор канала;
- работающая отправка: `POST https://platform-api2.max.ru/messages?chat_id=<MAX_ALERT_CHAT_ID>` с заголовком `Authorization: <MAX_ALERT_TOKEN>` и телом `{"text": "...", "format": "html"}` — или просто `npm run max:send -- "текст"`.
