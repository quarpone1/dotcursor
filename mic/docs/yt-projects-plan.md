# План: клиники видят свои задачи в MIC, бот заполняет поля по-новому

Статус: **согласован, бот доработан**. Роль, группы и видимость заводит `npm run youtrack:setup`. Вариант «видимость в MIC» согласован с Дмитрием
вместо отдельных проектов по объектам.

## Как будет работать

- MIC остаётся единственным местом, где живут заявки: инженеры работают и пишут
  комментарии там, бот создаёт задачи там. Planfix как сейчас, параллельно.
- Каждой задаче бот ставит **ограниченную видимость**: группа клиники +
  команда MIC. Админ клиники, состоящий в группе своей клиники, видит в MIC
  только задачи своего объекта, с комментариями и статусами, сразу.
  Задачи других клиник ему не видны ни в списке, ни поиском.
- Отдельные проекты по объектам не создаются. Если позже понадобятся, это не
  мешает: группы останутся те же.

**Роль «Клиент МИЦ»** (новая). У существующей роли «Клиент» есть право менять и
удалять задачи, для общего проекта это лишнее. Новая роль: читать задачи и
комментарии, писать комментарии, прикладывать файлы, видеть отчёты. Без
изменения полей, статусов и удаления.

## Доработка бота MAX

| Что | Как |
|---|---|
| Видимость | Группа клиники + команда MIC на каждой задаче. |
| «Объект» | По клинике: ГП-1 → ГП1, ТГМУ → ТюмГМУ, Нефтяник Здоровье → Здоровье и т. д. |
| «Где выявлено» | То же значение, только для «Тип заявки» = Ошибка. |
| «Месяц создания» | `ГГГГ.ММ` по дате оформления; нового месяца в списке нет — бот добавит. |
| Исполнитель | Поле «Разработчик» = инженер клиники (уже так). |
| «Тип» | Ошибка → Bug, Доработка → Task (в интерфейсе «Задание»). |
| «Номер заявки» | Поле больше не заполняется. В MAX заявка называется номером YouTrack: «Заявка MIC-12 принята», ссылка `https://yt.medinfocenter.ru/issue/MIC-12` без названия задачи. В «Моих заявках» и заголовках ответов тоже MIC-N. |

Что видит клиент: все комментарии задачи. Если инженеру нужно обсудить что-то
без клиента, в YouTrack у комментария есть своя видимость «только команда».
